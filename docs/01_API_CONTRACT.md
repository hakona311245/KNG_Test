# KNG Fashion API Contract

This document defines the planned MVP API surface. Swagger/OpenAPI should be generated by the NestJS backend and kept consistent with this contract.

## API Conventions

### Base Path

```text
/api
```

### Auth

JWT authentication uses HttpOnly cookies:

- `access_token`: short-lived JWT.
- `refresh_token`: rotating refresh token.

Tokens must not be stored in localStorage. Refresh-token rotation is required. Refresh tokens or refresh sessions must be stored hashed in the database.

### Roles

- `CUSTOMER`
- `ADMIN`

### Customer Statuses

- `ACTIVE`
- `BLOCKED`
- `INACTIVE`

Blocked or inactive customers cannot log in or place orders.

### Product Types

- `SHIRT`
- `PANT`
- `JACKET`

Product types are fixed for MVP. There is no product type CRUD API in the first version.

### Sizes

- `S`
- `M`
- `L`
- `XL`

Sizes are fixed for MVP. There is no size CRUD API in the first version.

### Colors

Colors are free-text values stored on product variants.

### Payment Options

- `COD`
- `VNPAY`

Both payment options route through mock payment behavior for MVP. Mock payment always succeeds.

### Order Statuses

- `PENDING`
- `CONFIRMED`
- `PROCESSING`
- `SHIPPED`
- `DELIVERED`
- `CANCELLED`

### Common Response Shape

```json
{
  "data": {},
  "message": "Success"
}
```

### Common Error Shape

```json
{
  "statusCode": 400,
  "message": "Validation failed",
  "error": "Bad Request"
}
```

## User Service

The User service owns authentication, user identity, customer account status, roles, and refresh sessions.

Total MVP endpoints: 8

### Endpoint Overview

```http
POST /api/auth/register
POST /api/auth/login
POST /api/auth/refresh
POST /api/auth/logout
GET /api/auth/me
GET /api/admin/customers
GET /api/admin/customers/:id
PATCH /api/admin/customers/:id/status
```

### Register Customer

```http
POST /api/auth/register
```

Request:

```json
{
  "email": "customer@example.com",
  "fullName": "Nguyen Van A",
  "password": "StrongPassword123",
  "phoneNumber": "0900000000"
}
```

Response:

```json
{
  "data": {
    "id": "user-id",
    "email": "customer@example.com",
    "fullName": "Nguyen Van A",
    "phoneNumber": "0900000000",
    "role": "CUSTOMER",
    "status": "ACTIVE"
  },
  "message": "Customer registered successfully"
}
```

### Login

```http
POST /api/auth/login
```

Request:

```json
{
  "email": "customer@example.com",
  "password": "StrongPassword123"
}
```

Response:

```json
{
  "data": {
    "user": {
      "id": "user-id",
      "email": "customer@example.com",
      "fullName": "Nguyen Van A",
      "phoneNumber": "0900000000",
      "role": "CUSTOMER",
      "status": "ACTIVE"
    }
  },
  "message": "Logged in successfully"
}
```

Set-Cookie:

```text
access_token=...; HttpOnly; Path=/; SameSite=Lax
refresh_token=...; HttpOnly; Path=/api/auth; SameSite=Lax
```

Blocked or inactive users must receive an authentication error and no auth cookies.

### Refresh Token

```http
POST /api/auth/refresh
```

Behavior:

- Validates the current refresh token from HttpOnly cookie.
- Validates the user is active.
- Rotates refresh token.
- Stores only the hashed refresh token/session value in database.
- Issues new access and refresh cookies.

### Logout

```http
POST /api/auth/logout
```

Behavior:

- Invalidates the current refresh session.
- Clears auth cookies.

### Current User

```http
GET /api/auth/me
```

Auth: `CUSTOMER` or `ADMIN`

Response:

```json
{
  "data": {
    "id": "user-id",
    "email": "customer@example.com",
    "fullName": "Nguyen Van A",
    "phoneNumber": "0900000000",
    "role": "CUSTOMER",
    "status": "ACTIVE"
  },
  "message": "Current user retrieved successfully"
}
```

### List Customers

```http
GET /api/admin/customers
```

Auth: `ADMIN`

Query parameters:

- `status`: `ACTIVE`, `BLOCKED`, `INACTIVE`
- `page`
- `limit`

### Get Customer Detail

```http
GET /api/admin/customers/:id
```

Auth: `ADMIN`

### Update Customer Status

```http
PATCH /api/admin/customers/:id/status
```

Auth: `ADMIN`

Request:

```json
{
  "status": "BLOCKED"
}
```

Customers are not permanently deleted in the MVP.

## Product Service

The Product service owns product catalog reads, admin product management, fixed product type options, fixed size options, free-text variant colors, variant stock, and product soft delete.

Total MVP endpoints: 12

### Endpoint Overview

```http
GET /api/products
GET /api/products/:id
GET /api/products/options
GET /api/admin/products
POST /api/admin/products
GET /api/admin/products/:id
PATCH /api/admin/products/:id
DELETE /api/admin/products/:id
GET /api/admin/products/:productId/variants
POST /api/admin/products/:productId/variants
PATCH /api/admin/variants/:variantId
DELETE /api/admin/variants/:variantId
```

### List Products

```http
GET /api/products
```

Query parameters:

- `type`: `SHIRT`, `PANT`, `JACKET`
- `size`: `S`, `M`, `L`, `XL`
- `color`: free-text color name
- `page`
- `limit`

Response:

```json
{
  "data": {
    "items": [
      {
        "id": "product-id",
        "name": "Essential Shirt",
        "type": "SHIRT",
        "material": "Cotton",
        "price": 250000,
        "imageUrl": "https://example.com/placeholder.jpg",
        "availableColors": ["Black", "White"],
        "availableSizes": ["S", "M", "L"],
        "isActive": true
      }
    ],
    "page": 1,
    "limit": 12,
    "total": 1
  },
  "message": "Products retrieved successfully"
}
```

Only active, non-deleted products should be returned to customers.

### Get Product Detail

```http
GET /api/products/:id
```

Response:

```json
{
  "data": {
    "id": "product-id",
    "name": "Essential Shirt",
    "description": "Daily cotton shirt",
    "type": "SHIRT",
    "material": "Cotton",
    "price": 250000,
    "imageUrl": "https://example.com/placeholder.jpg",
    "isActive": true,
    "variants": [
      {
        "id": "variant-id",
        "size": "M",
        "color": "Black",
        "stock": 10,
        "isActive": true
      }
    ]
  },
  "message": "Product retrieved successfully"
}
```

Product price is stored on the product. All variants of the same product use the same product price.

### Get Product Options

```http
GET /api/products/options
```

Response:

```json
{
  "data": {
    "types": ["SHIRT", "PANT", "JACKET"],
    "sizes": ["S", "M", "L", "XL"]
  },
  "message": "Product options retrieved successfully"
}
```

Colors are intentionally not returned as managed options because colors are free text on variants.

### List Admin Products

```http
GET /api/admin/products
```

Auth: `ADMIN`

Query parameters:

- `type`: `SHIRT`, `PANT`, `JACKET`
- `includeDeleted`: boolean
- `page`
- `limit`

### Create Product

```http
POST /api/admin/products
```

Auth: `ADMIN`

Request:

```json
{
  "name": "Essential Shirt",
  "description": "Daily cotton shirt",
  "type": "SHIRT",
  "material": "Cotton",
  "price": 250000,
  "imageUrl": "https://example.com/placeholder.jpg"
}
```

### Get Admin Product Detail

```http
GET /api/admin/products/:id
```

Auth: `ADMIN`

### Update Product

```http
PATCH /api/admin/products/:id
```

Auth: `ADMIN`

Request:

```json
{
  "name": "Updated Essential Shirt",
  "description": "Updated description",
  "type": "SHIRT",
  "material": "Cotton",
  "price": 260000,
  "imageUrl": "https://example.com/placeholder.jpg",
  "isActive": true
}
```

### Soft Delete Product

```http
DELETE /api/admin/products/:id
```

Auth: `ADMIN`

Behavior: soft delete only.

### List Product Variants

```http
GET /api/admin/products/:productId/variants
```

Auth: `ADMIN`

### Create Product Variant

```http
POST /api/admin/products/:productId/variants
```

Auth: `ADMIN`

Request:

```json
{
  "size": "M",
  "color": "Black",
  "stock": 10
}
```

Rules:

- `size` must be one of `S`, `M`, `L`, `XL`.
- `color` is free text.
- The same product cannot have duplicate active variants with the same size and color.

### Update Product Variant

```http
PATCH /api/admin/variants/:variantId
```

Auth: `ADMIN`

Request:

```json
{
  "size": "L",
  "color": "Black",
  "stock": 12,
  "isActive": true
}
```

### Soft Delete Product Variant

```http
DELETE /api/admin/variants/:variantId
```

Auth: `ADMIN`

Behavior: soft delete only.

## CartAndOrder Service

### Endpoint Overview

```http

POST /api/cart/items
PATCH /api/cart/items/:itemId
DELETE /api/cart/items/:itemId
POST /api/checkout
GET /api/orders
GET /api/orders/:id
POST /api/orders/:id/cancel-request
GET /api/admin/orders
GET /api/admin/orders/:id
PATCH /api/admin/orders/:id/status
POST /api/admin/orders/:id/cancel
```

### Get Cart

```http
GET /api/cart
```

Auth: `CUSTOMER`

Response:

```json
{
  "data": {
    "id": "cart-id",
    "items": [
      {
        "id": "cart-item-id",
        "variantId": "variant-id",
        "productId": "product-id",
```

### Checkout

```http
POST /api/checkout
```

Auth: `CUSTOMER`

Request:

```json
{
  "shippingName": "Nguyen Van A",
  "phone": "0900000000",
  "address": "123 Nguyen Trai",
  "city": "Ho Chi Minh City",
  "note": "Call before delivery",
  "paymentOption": "COD"
}
```

Behavior:

- Validates customer account status is `ACTIVE`.
- Validates cart ownership.
- Validates variant stock.
- Runs mock payment.
- Mock payment always succeeds.
- Creates order and order items.
- Stores price snapshot on each order item.
- Reduces stock after successful mock payment.
- Clears cart.

Response:

```json
{
  "data": {
    "orderId": "order-id",
    "status": "PENDING",
    "paymentOption": "COD",
    "paymentStatus": "PAID",
    "total": 500000
  },
  "message": "Order placed successfully"
}
```
